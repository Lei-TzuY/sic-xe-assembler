# Reaching definitions and function contracts

The CFG analyzer now carries a classical forward reaching-definitions layer in
addition to exact constants, signed intervals, condition facts, and backward
liveness.

## Definition identities

Definitions have deterministic IDs:

- `D04003:A` — instruction at `0x04003` defines register `A`.
- `E04020:B` — function entry `0x04020` receives an unknown incoming `B` value.

Every statically discovered function entry (the manifest execution entry plus
resolved `JSUB` targets) receives pseudo-definitions for `A/X/L/B/S/T/CC`.
These are not invented values. They identify values supplied by the caller or
environment without assigning a numeric value to them.

## Forward GEN/KILL dataflow

For each instruction, the analysis records:

- `reaching_in`: definitions that may reach the instruction before execution;
- `reaching_out`: definitions that may reach its successors;
- `use_definitions`: reaching definitions for every explicitly used value;
- `definition_ids`: definitions generated by the instruction;
- `unresolved_uses`: explicit uses for which no represented definition reaches.

A definition kills prior definitions of the same value and generates its own
identity. CFG joins take set union. Consequently, if two branches define `A`
and later merge at `STA`, both definition IDs remain attached to the `A` use.
The analyzer never chooses one path merely to make the result look precise.

Calls use the same caller-side summary model as liveness: the resolved call edge
is not a normal dataflow edge; the call instruction itself generates `L` and
summary-proven clobbers, and its fallthrough carries those definitions. Callee
entries are analyzed independently from their entry pseudo-definitions.
Synthetic `RSUB -> continuation` edges remain structural proof and are not used
as context-free reaching-definition edges.

## Def-use chains

`def_use_chains` invert the use relation. Each definition lists every represented
instruction use it may feed. A chain with no explicit use is **not automatically
dead**: a definition may be observable as a function output. `dead_definitions`
is emitted only when the backward liveness layer independently proves the write
unobservable on represented successors/exits.

## Function contracts

Function objects are enriched with dataflow-derived interface evidence:

- `required_inputs`: entry pseudo-values that feed an explicit use in the body;
- `input_use_sites`: the instructions consuming each required input;
- `passthrough_inputs`: entry values reaching every represented `RSUB` unchanged;
- `partially_preserved_inputs`: entry values reaching some but not all returns;
- `overwritten_inputs`: entry values reaching no represented return;
- `produced_outputs`: values with a local instruction definition reaching at
  least one represented return;
- `output_definitions`: exact local definition IDs supporting each output.

These are not calling-convention declarations. They summarize only represented,
statically resolved control flow. A function with no represented return does
not claim a return-state contract. Unknown calls and unresolved control flow
remain conservative.

## Trust boundary

Reaching definitions identify *where a value may have been defined*, not what
the value is. Numeric claims remain the responsibility of exact/range abstract
interpretation. Likewise, def-use evidence does not imply an instruction can be
removed: memory writes, I/O, calls, traps, and other side effects remain governed
by the liveness/side-effect model.
