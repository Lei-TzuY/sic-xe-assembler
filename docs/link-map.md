# Link-map artifact

The loader emits a deterministic `.map` file after a complete load plan has been validated and before memory is materialized. The map is a review/debug artifact: it records the exact link decisions that produced the final image rather than dumping transient console state.

## File naming

For a normal invocation such as:

```powershell
python loader.py program.obj 4000
```

the report is written beside the first object input as `program.map`. With multiple object inputs, the first input still owns the output stem because one invocation produces one linked image.

The loader removes an existing map before planning. If parsing, placement, symbol resolution, relocation arithmetic, or entry-point validation fails, no stale map is left behind.

## Deterministic ordering

The report is intentionally stable for code review and regression diffs:

- control sections follow input-file and object-section order;
- external symbols are sorted by symbol name;
- cross-reference symbols are sorted by symbol name while each symbol's uses preserve relocation/source order;
- relocations preserve section and field order from the validated load plan;
- unused `R` declarations preserve section order and use sorted symbol names.

No timestamps, random identifiers, host paths generated by the loader, or memory-dependent values are added.

## Report sections

`CONTROL SECTIONS` lists each section's source origin, final load address, end-exclusive loaded end, length, input index, and object-file provenance.

`EXTERNAL SYMBOLS` is the final ESTAB. It distinguishes control-section symbols from `EXTDEF` symbols and carries the definition provenance retained by the load plan.

`CROSS REFERENCES` answers which relocation terms reference each external symbol. Every use records its sign, referencing control section, source-object M-record address, final loaded relocation site, field width, and input file.

`UNUSED R DECLARATIONS` lists external references that were declared in an `R` record but did not participate in any `M` expression. They are legal metadata, not link failures.

`RELOCATIONS` exposes the exact prevalidated arithmetic for every relocation field: source/load site, width, original addend, summed ESTAB delta, final value, encoded field, and signed symbol terms. This makes a linked byte explainable without reverse-engineering the final memory image.

The header records `PROGADDR`, linked-image end/length, and execution-entry provenance. The final summary gives section, symbol, relocation, and unused-reference counts.

## API

`link_map.render_link_map(plan)` returns the complete UTF-8 report text.

`link_map.write_link_map(plan, path)` writes it atomically through a temporary sibling file and returns the final path. The renderer consumes only an already validated `LoadPlan`; it does not perform new symbol resolution or relocation arithmetic.
